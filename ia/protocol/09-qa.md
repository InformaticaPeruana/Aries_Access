# 09 — QA de camino de usuario

La evidencia de un AC funcional debe recorrer **el mismo camino que el usuario**. Una prueba que consulta la base de datos demuestra que el almacén guardó algo; no demuestra que el usuario pueda hacerlo.

## Superficies

Cada superficie tiene su forma de evidencia:

| Superficie | Evidencia aceptable |
|---|---|
| Web / UI | Navegador real: petición HTTP real, captura, `console` sin errores |
| API | Llamada HTTP real con status y payload (`curl`/`fetch`), guardada en `ia/.harness/` |
| CLI | Comando real con su salida y exit code |
| Job / worker / cola | Ejecución real y efecto observable (fila, archivo, mensaje) |
| Webhook / integración | Entrega real y respuesta del receptor |

`PASS` sin uno de estos artefactos es una afirmación, no una validación.

## Camino de humo (smoke)

Define **un** camino de humo por aplicación: el recorrido mínimo que cruza las piezas críticas. Ejemplo de forma (adáptalo):

```
login → <acción principal> → <efecto observable> → <cierre/confirmación>
```

Se ejecuta antes de cerrar cualquier feature que toque esas piezas, y su resultado va al TRACKING.

## Automatización del navegador

Cuando la superficie es web, automatiza en vez de clickear a mano: produce evidencia repetible y deja artefactos (capturas, logs, respuestas).

El motor se resuelve con [`../qa/driver.mjs`](../qa/driver.mjs), que sondea y elige en este orden:

1. **playwright** — si está instalado en el proyecto. API en proceso: auto-wait, aserciones, trace.
2. **cdp** — propio de `ia/` ([`../tools/browser-cdp.mjs`](../tools/browser-cdp.mjs)), **sin dependencias**: usa el Chrome o Edge ya instalado. Es el motor por defecto.
3. **gstack** — checkout externo, opcional. Ninguna prueba debe depender de él.

La columna `Evidencia` **registra el motor** que produjo el resultado (`engine=cdp`): dos corridas con motores distintos no son comparables. Política completa en [DEC-0015](../decisions/DEC-0015-motores-qa.md); uso y autoprueba en [`../qa/README.md`](../qa/README.md).

Contratos: [`../qa/smoke.example.mjs`](../qa/smoke.example.mjs) (HTTP, sin navegador) y [`../qa/form.example.mjs`](../qa/form.example.mjs) (formulario por capas). Autoprueba del motor: `node ia/qa/selftest-cdp.mjs`.

Si no puedes automatizar, la prueba manual **también** produce artefacto: captura + la línea de log que demuestra el efecto. "Lo probé y funciona" no es evidencia.

## Sesión real (perfil del usuario)

Para pruebas que necesitan una sesión **que no se puede scriptear** —2FA, SSO, un entorno de un cliente, o un SPA con el token en `localStorage`— el motor puede usar tu perfil real de Chrome o Edge:

```js
const s = await createSession({ profile: 'real' });   // requiere el navegador CERRADO
console.log(s.profileKind, s.profile);                // 'usuario', y la ruta
```

Tres cosas que hay que saber antes de usarlo:

1. **El navegador tiene que estar cerrado.** Si no, el proceso nuevo delega en el que ya corre, el puerto de depuración no abre, y además se abre una ventana en tu navegador. El motor lo comprueba y falla con ese mensaje en vez de dejarte adivinando.
2. **Es tu sesión real:** tus logins, tu historial. No es una operación rutinaria; se trata como gate ([`08-gates.md`](./08-gates.md)).
3. **Un perfil del usuario nunca se borra.** El motor solo borra los perfiles temporales, que son el comportamiento por defecto.

Y el motivo de que exista: un token guardado en `localStorage` **no** está en la base de cookies, así que importar cookies no habría autenticado nada. El perfil sí.

Autoprueba: `node ia/qa/selftest-perfil.mjs` (8 comprobaciones, sin tocar tu perfil).

Ver [DEC-0017](../decisions/DEC-0017-perfil-real-navegador.md).

## Qué NO es evidencia

- Consultar la BD y ver la fila.
- Un test unitario del servicio sin pasar por la capa de entrada.
- Un `200 OK` sin comprobar el payload.
- Una captura sin indicar qué se estaba probando.
- La palabra de un subagente sobre su propio trabajo.
